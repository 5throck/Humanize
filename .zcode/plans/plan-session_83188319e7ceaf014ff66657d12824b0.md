# Humanize — 장문 청킹 포팅 + API/MCP 제공 + PR 병합 계획

## 배경 (탐색 결과)

- **upstream 청킹**: im-not-ai는 15,000자+에서 청킹 권장, 목표 7,000자/상한 9,000자/문단 4,000자 초과 시 문장 경로 폴백. 헤딩 앞 강제 분할(청크가 헤딩으로 끝나지 않게 glue), 말미 각주 블록 passthrough, **offset 구간 기반 무손실 분할**(연결 시 원문과 정확히 일치 self-check), 청크별 `[청크 컨텍스트]` 헤더(서두/결말 새로 만들기 금지), 병렬 ≤4 처리, 병합 시 공백 복원 + 청크별 글자 비율 경고(0.5x 미만 유실 / 2.0x 초과 증식) + 변경률 게이트. upstream 단서: "웹앱의 1,800자 청크는 flash-lite 전제라 이식 금지 — 큰 모델은 문단 횡단 신호를 잡아야 하므로 청크가 커야 한다" → **upstream 상수(15k/7k/9k/4k)를 그대로 채택**.
- **현 서비스**: serve.ts(node:http, 제로 디펜던시, 127.0.0.1:8765)에 LLM 프록시 4개 엔드포인트만 있고 규칙 엔진은 브라우저 전용. MCP 전무. rules.js/prompt.js는 DOM 없는 IIFE라 Node에서 `new Function('window', src)`로 재사용 가능(test.mjs가 이미 사용).
- **GitHub**: `github.com/5throck/Humanize` public + MIT (유지 확정). 지난 회차 upstream 동기화 6개 파일 미커밋.

## PR 2 — `feat/chunking-api-mcp` (신규 기능)

### 1. `chunking.js` (신규, rules.js와 같은 window-IIFE 패턴)
`window.HumanizeChunking` 제공:
- `plan(text, opts?)` — upstream `compute_chunk_spans` 포팅: 헤딩 라인 감지(`#`, `N.`, `N)`, `제N장/절/편`, 로마자, `가.` 등) 강제 분할 + 헤딩 glue(청크 끝 = 헤딩 금지), 공백줄 문단 단위 greedy packing(target 7,000/max 9,000), 4,000자 초과 문단 문장 경로 폴백, 말미 각주(`^\d+\)\s`, `^\[\d+\]\s`) passthrough, 무손실 self-check(실패 시 예외). 15,000자 미만은 `recommended: false` 단일 청크.
- `chunkHeader(index, total, startsWithHeading)` — upstream `[청크 컨텍스트]` 문구 포팅.
- `merge(original, plan, parts)` — 개수/빈 결과 검사, 공백 복원(trim 후 원 청크 선행/후행 공백 재부착 — "원문 그대로면 재조립 = 원문" 항등 보장), 청크별 글자 비율 경고(0.5/2.0), passthrough 청크는 LLM 호출 없이 원문 복사. `{ text, warnings }` 반환.
- opts로 target/max 오버라이드 허용(하한 2,000 clamp, flash-lite 경고 주석).

### 2. `lib/engine.mjs` (신규 로더)
rules.js/prompt.js/chunking.js를 샌드박스로 로드해 `{ Rules, Prompt, Chunking }` 반환. serve.ts와 mcp-server.mjs가 공용.

### 3. `serve.ts` — HTTP API 5개 엔드포인트 추가
JSON 본문 파서 추가 후 (엔진은 기동 시 1회 로드):
- `POST /api/analyze` `{text}` → findings/s1/s2/total
- `POST /api/polish` `{text}` → `{text, applied, before, after, changeRate, grade}`
- `POST /api/prompt` `{genre?}` → system prompt
- `POST /api/chunk` `{text, target?, max?}` → `{recommended, chunks:[{index,total,text,header,passthrough}]}`
- `POST /api/merge` `{original, rewritten[]}` → `{text, warnings, changeRate, grade}`
입력 30,000자 캡(프론트와 동일), JSON 오류 400, 기존 CORS 정책 그대로.

### 4. `mcp-server.mjs` (신규, 제로 디펜던시 stdio MCP)
newline-delimited JSON-RPC 2.0 최소 구현: `initialize`/`ping`/`tools/list`/`tools/call`(notifications 무시). 로그는 stderr만. 도구 5개(HTTP API와 동일 페이로드): `humanize_analyze`, `humanize_polish`, `humanize_prompt`, `humanize_chunk`, `humanize_merge`. `import.meta.url` 직접 실행 판별로 모듈 import 시 프로토콜 루프 미기동(테스트 가능). README에 `claude mcp add humanize -- bun mcp-server.mjs` 등록법 기술.

### 5. `app.js` LLM 모드 청킹 연동
15,000자 이상 입력 시: `plan()` → 본문 청크만 HumanizePrompt.system(genre)+청크 헤더로 병렬 호출(≤4, 진행 상태 표시), passthrough는 원문 유지, `merge()` 후 경고 표시. 미만은 기존 단일 호출 경로. `index.html`에 chunking.js 스크립트 태그 추가.

### 6. 테스트 (`test.mjs` 확장)
- 청킹: 무손실 왕복(헤딩·문단·각주 혼합 문서), 청크가 헤딩으로 끝나지 않음, 각주 passthrough, 4,000자+ 문단 문장 폴백, 병합 항등(원문 재투입 시 재조립=원문), 비율 경고 트리거, 15k 미만 단일 청크.
- MCP: tools/list 5개, humanize_analyze/humanize_polish 호출 결과, initialize 핸드셰이크 핸들러.
- serve.ts 엔드포인트는 얇은 래퍼라 단위 테스트 제외(CI의 `bun build serve.ts`가 문법 검증).

### 7. 문서·레지스트리
- `references.json`: im-not-ai adopted에 청킹 파이프라인 포팅 기록(상수·알고리즘·병합 검증, upstream 상수 채택 근거 포함). deferred에 "문서 단위 진단 1콜 공유"(진단 에이전트 없음), "경계 이음매 국소 패치(2문단)" 추가. last_checked는 유지(청킹은 기존 코드, 신규 드리프트 아님).
- `README.md`: API 엔드포인트 표+curl 예시, MCP 등록법+도구 표, 아키텍처 노트.
- CI(`.github/workflows/ci.yml`): `node --check mcp-server.mjs` 추가.
